# 多保命 護理線上做題網站 — 功能規格文件

> 用途:提供給下一階段設計(Opus / Sonnet)作為介面與架構設計依據
> 版本:v1 draft
> 對應專案:rnhighpass.com / 多保命 護理分章詳解

---

## 一、專案基本資訊

- **產品定位**:延伸「多保命 護理分章詳解」題庫內容,做成線上做題 + 筆記整理的網站
- **目標使用者**:準備護理國考的學生(學弟妹),免費使用為主
- **預估規模**:每年約 1,000 活躍使用者(護理國考總報考人數約 10,000 人,取保守估計),需視口碑成長再調整
- **既有素材**:分章題庫已結構化為 Markdown + JSON(含章節/子章節分類、考點標籤),可直接作為資料來源

---

## 二、視覺風格

- **主色調**:藍色系,考慮沿用講義既有的莫蘭迪色階,但不強制:
  - light `#D7E1F2`
  - mid `#B6CCF0`
  - accent `#6592CD`
  - deep `#2C5A96`
- **設計要求**:整體要有設計感,不一定要完全套用上述色票,可依實際 UI 需求微調
- **裝置優先順序**:手機與電腦**平行兼顧**,需同時做好響應式設計(通勤/等車用手機,坐下讀書用電腦)

---

## 三、核心功能模組

### 1. 小筆記區(考點整理)
- 內容形式:文字整理 + **搭配圖片/圖解** + **相關考題**
- 需要**分類標籤篩選功能**(可沿用現有分章題庫的章節/子章節/考點標籤體系)
- 與測驗區為**整合式**串接:使用者點進某個筆記/考點,頁面下方直接接該考點的相關題目(不是分開的兩個獨立入口)

### 2. 測驗區
- 出題模式(皆需支援):
  - 依單元/章節隨機出題
  - 全真模擬考(計時、整份考卷)
  - 錯題重做
  - 依考點/標籤自選出題
- **錯題本邏輯**:答錯自動收錄(不需使用者手動標記)

### 3. 帳號系統
- 登入方式:**Google 一鍵登入**(不需另外做 email/密碼系統)
- 登入後可記錄:
  - 作答紀錄(優先)
  - 錯題本(答錯自動收錄)

### 4. 統計/進度儀表板
- 範圍:**小規模統計**即可,不需完整學習儀表板
- 內容:章節正確率(依現有分章結構呈現)

---

## 四、MVP(第一版)範圍

- 目標:**筆記區 + 測驗區一起做,但先做小規模 demo**(先選少數幾個章節完整跑通,而非全部章節一次上線)
- 換句話說:MVP 要能完整展示「筆記 → 相關題目 → 測驗 → 錯題自動收錄 → 章節正確率統計」這條完整體驗流程,但涵蓋章節數量先求少而精

---

## 五、技術與預算考量(供設計/開發階段參考)

- 既有技術方向:前端曾評估 Firebase vs Supabase,傾向以結構化 JSON 作為資料庫無關的中介格式
- 靜態站點目前架設在 Cloudflare Pages(repo: `rnhighpass`,GitHub: JimmyinTaipei)
- **預算估算**(以年活躍使用者 ~1,000 人規模計):
  - Supabase 免費方案(50,000 MAU、500MB 資料庫、1GB 檔案儲存、5GB 頻寬/月)在此規模下**足夠免費使用**
  - Cloudflare Pages 前端 hosting 本身免費
  - 建議:圖片/圖解等靜態資源走 Cloudflare 而非 Supabase Storage,避免頻寬額度被圖片流量吃掉
  - 結論:目前規模下預估月成本 **$0**,除非使用者量大幅超出預期才需考慮升級付費方案(Supabase Pro 約 $25/月起)

## 六、留待設計階段決定的事項

以下是這份文件尚未鎖定、需要設計者進一步提案或與 Jimmy 確認的部分:

- 筆記區與測驗區整合頁面的具體版型(例如:筆記在上、題目在下 vs. tab 切換)
- 錯題本的呈現方式與複習提醒機制(是否需要間隔重複 / 排序邏輯)

- 模擬考計時介面與交卷後的結果頁設計
- 分類標籤篩選 UI(側邊欄 vs. 上方篩選列等)
- 手機版與電腦版的資訊架構差異(是否需要不同的導覽邏輯)

## 七、Design System(輕量版)

> 目的:作為不同設計階段(Opus / Sonnet)之間的共同語言,確保筆記頁、測驗頁、模擬考頁、統計頁、登入頁風格一致。非正式產品團隊規格書,僅列出核心 token 與元件狀態。

### 1. 色彩 Token

| Token | Hex | 建議用途 |
|---|---|---|
| `color-light` | `#D7E1F2` | 大面積背景、卡片底色 |
| `color-mid` | `#B6CCF0` | 次要背景、hover 底色、未選中狀態 |
| `color-accent` | `#6592CD` | 主要互動色(按鈕、連結、選中標籤、進度條) |
| `color-deep` | `#2C5A96` | 標題文字、強調文字、focus 邊框 |

補充建議(規格文件本身未指定,交由設計階段決定,但建議至少納入):
- **中性色階**(文字用):純黑/純白之外,至少一組深灰(內文)、淺灰(輔助說明文字、placeholder)
- **語意色**(測驗必要):正確(綠色系)、錯誤(紅/橘色系)、警示(計時倒數用),需與藍色主色系搭配協調,不搶主色風采
- 深色模式:此版本先不列入需求,除非之後明確提出

### 2. 字體階層

尚未指定字體家族,建議設計階段依「有設計感」的要求挑選一組中英文皆清晰易讀的字體組合(例如強調中文可讀性的無襯線字體),並至少定義以下階層:

| 層級 | 用途 |
|---|---|
| H1 | 頁面主標題(如章節名稱) |
| H2 | 區塊標題(如「相關考題」「錯題本」) |
| Body | 筆記內文、題目文字 |
| Caption / Small | 標籤、時間戳記、輔助說明 |

### 3. 間距與版面

- 建議採用一致的間距倍數系統(例如 4px 或 8px 為基準單位),避免不同頁面元件間距各自為政
- 手機/電腦需分別定義內容最大寬度與邊界留白,確保響應式切換時版面不會跑版

### 4. 核心元件與狀態(至少需涵蓋)

- **按鈕**:預設 / hover / disabled 狀態
- **選項卡(測驗選項)**:未選 / 選中 / 答對(正確)/ 答錯(錯誤)/ 顯示正解 等狀態,顏色需與語意色對應且清楚可辨識
- **標籤 Tag(考點/分類篩選用)**:未選中 / 選中 / hover 狀態
- **卡片(筆記卡、統計卡)**:預設樣式、陰影或邊框處理方式
- **計時器(模擬考用)**:一般狀態、時間剩餘不多時的警示狀態
- **進度/統計圖表元件**:章節正確率呈現用的基礎樣式(圖表類型留待設計階段決定)

### 5. 交付給下一階段的建議格式

若後續要正式交給 Opus 或 Sonnet 執行視覺設計,建議這份 Design System 能延伸輸出為:
- 一組可重複使用的 CSS variables / Tailwind theme token
- 至少 1–2 個代表性頁面的高保真示意稿(如「筆記+相關題目整合頁」「測驗答題頁」),作為後續其他頁面比照的基準
