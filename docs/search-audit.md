## 使用者已提出的需求

- 先盤查所有搜尋功能，再調整；不同地方的搜尋方式要一致
- 可以有全局搜尋，也可以限定科目或知識庫
- 科目內搜尋應查該科底下的內容，例如題目與解答
- 知識庫搜尋應涵蓋內容文字、表格；是否納入考題尚待決定
- 各處統計須一致且說明題目範圍，不能只修一個系統頁的篇數
- 2026-11-02 補充：結果不能整列無限往下堆，一定數量後分頁；搜尋結果區統一為知識庫風格的白底，移除灰底結果框；其他問題等本輪修正後再安排

## 本輪實作與驗證（2026-11-02）

### 第五輪：閱讀位置、搜尋等待畫面與相關性排序

- 後續依使用者要求刪除「全部」下的搜尋內容／各類預覽數量說明，以及知識庫、考古題的搜尋與分頁說明、顯示內容下方的補充文字；實際搜尋規則與預覽數量維持原設定。知識庫類型膠囊上方新增「類型篩選」，標籤樣式比照「顯示內容」

- 使用者同意加入返回原本閱讀位置、搜尋中保留畫面與關鍵字，以及細調相關性排序
- 從結果前往文章、段落、題目或表格後，返回搜尋會依原本的關鍵字、篩選與頁碼還原捲動位置，以及題目、文章更多符合項目與章節篩選的展開狀態；表格的返回搜尋連結也使用相同還原流程
- 閱讀狀態只存在目前分頁的 sessionStorage，最多保留最近 12 組搜尋；儲存被瀏覽器封鎖時仍可正常搜尋。重新搜尋、切換篩選及分頁會從新結果頂端開始，避免套用舊的閱讀位置
- JavaScript 接手後使用導覽 transition 保留目前結果與輸入關鍵字，顯示「正在搜尋」提示並暫停重複送出搜尋框；完成後才切換結果。等待提示已依後續回饋改為結果區上方的白底強調外框提示，含旋轉載入圖示、「搜尋中，正在載入結果…」與保留結果說明；捲動時提示置頂，支援減少動態效果偏好；JavaScript 尚未載入時仍沿用可提交關鍵字與篩選的原生 GET 表單
- 知識庫相關性依序為：篇名完全符合、篇名開頭／包含、文章別名、段落／表格標題、純內文符合；同篇內仍保持文章原有階層與閱讀順序
- 型別、修改檔案 ESLint 與 17 項回歸測試通過，涵蓋排序、閱讀狀態分離／清除、儲存受限與容量淘汰；本機 HTTP 已確認篇名完全符合優先、穩定展開識別與原生表單。等待畫面及實際返回捲動的瀏覽器互動尚待人工驗收，未部署，未另行啟動或關閉 dev
- 人工驗收：搜尋後展開題目或文章更多項目並往下捲，開啟結果再返回，確認位置與展開狀態；再換字搜尋、套用篩選與重搜相同關鍵字，確認等待期間保留畫面，完成後回到新結果頂端

### 搜尋送出遺失關鍵字修正（2026-11-02）

- 使用者回報自行啟動 `pnpm dev` 後，輸入關鍵字按搜尋，載入後回到空白搜尋頁
- 查到搜尋框僅靠 `onSubmit`／React state 呼叫 router，HTML 表單缺少 action，輸入欄位也沒有 `name="q"`；JavaScript 尚未接手時原生送出不會攜帶關鍵字，這個缺口可造成上述現象
- 改為 Next.js `Form action="/search"`，輸入欄具備 `name="q"`，有效範圍／類型透過 hidden input 送出；瀏覽器原生 GET 與 JavaScript 導覽都能保留關鍵字，不再依賴 React state 的輸入事件
- 抽出共用 `searchParameters()`，分頁連結與原生表單採用同一套適用條件規則
- 新增原生表單送出的回歸測試，涵蓋全站、本科／本章、知識庫類型、表格範圍；目前共 6 項搜尋測試通過，型別與本輪 ESLint 亦通過
- 用使用者正在運行的本機 dev 讀取實際 HTML 表單，再依其具名欄位送出 GET，確認 q、scope、type 保留；這次未另外啟動 dev，也未關閉使用者自己的 dev
- 上一輪 HTTP 測試是直接請求帶 q 的網址，沒有覆蓋瀏覽器送出前的表單序列化，因此漏掉這個缺口；上述回歸測試補足此部分，實際瀏覽器點擊仍待使用者重測

## 現在到底搜了什麼

主要查詢來源：`src/lib/data.ts` 的 `searchContent()`／`searchQuestionsByRef()`、`src/lib/knowledge/index.ts` 的 `searchKnowledge()`；知識庫索引由 `scripts/build-knowledge.mjs` 的 `searchOutput()`／`plainText()` 建置

### 既有查詢與顯示問題

- 知識庫類型篩選列包在「有知識庫結果」內，篩到零筆後整排消失，無法看出或直接解除目前類型
- 再次送出 SearchBox 只帶 q 和 scope，原本 type 會消失；切 scope 也清除 type，須先訂一致的保留規則
- 搜尋頁即使限定知識庫，仍呼叫題庫／筆記查詢；限定考古題也仍呼叫知識庫搜尋，分類顯示與資料查詢範圍不同
- 知識庫最多回傳 60 筆，但畫面從 50 筆就加「以上」；無確切總命中數／hasMore，篇與段落也混稱筆數
- 題幹、考點、筆記卡、bullet 各查詢最多 50 筆，合併後數量不等於總命中數；題目與卡片共用 truncated 旗標，可能彼此影響「以上」顯示，沒有分頁
- 題目搜尋列預覽只有題幹，若只在考點命中，收合時看不出為何出現；擴充詳解後更需要命中欄位與片段
- 題目用 `primary_chapter_id` 顯示所在章節；科目／章節取題另外有 topics 關聯，不能直接拿主章節欄位當本科搜尋的唯一歸屬規則

## 建議的一致操作規格（尚未實作）

### 範圍與內容種類分開

| 入口 | 建議預設範圍 | 建議搜尋內容 |
|---|---|---|
| 全站搜尋 | 全站 | 知識庫文章／段落／表格、各科題目／解答／章節筆記、舊比較表，結果分組且去重 |
| 科目章節頁 | 本科，例如「內外科護理」；另可明確切本章或全站 | 本科題幹、選項、考點、正解原因、錯誤選項說明、補充及舊詳解；本科筆記、比較表 |
| 知識庫瀏覽 | 整個知識庫，清楚顯示範圍 | 知識庫文字與表格標題／表頭／內容；系統、類型、小兒可作額外篩選 |
| 比較表頁 | 表格集合，科目限制明示且可切換 | 表名與內容；銜接同一搜尋規則與結果格式，資料合併另案處理 |

- 「範圍」回答在哪裡找（全站／本科／本章／知識庫），「內容種類」回答找什麼（文章／表格／題目／筆記），避免所有選項混成一排
- 科目搜尋依實際章節歸屬取得題目，再依 ID 去重；跨章／跨科題怎麼納入須和 P7 統計口徑一起定義
- 關聯知識文章不宜只因被本科引用就自動算成本科正文；若納入，須另列「本科相關知識」並說明依據
- 知識庫是否納入考題仍未決：建議預設搜正文與表格，另外提供明確的「包含相關考題」選項；不可把知識文章的考題靜默混入正文結果
- 若採相關考題選項，需先決定用頁首整篇題集還是段落題集，並依 ID 去重；沿用 [knowledge-question-alignment.md](knowledge-question-alignment.md) 的來源差異紀錄，不為搜尋先行重分全庫考題

### 共通行為

1. 使用相同搜尋框與 Enter／搜尋按鈕送出；範圍在輸入前就看得到，按鈕與鍵盤操作一致
2. 關鍵字、範圍、科目／章節、類型等狀態寫入 URL，支援返回、重新整理與分享
3. 同範圍重搜保留有效篩選；切換範圍時只移除不適用條件，畫面同步更新；提供清除篩選
4. 零結果仍顯示範圍與篩選，優先提供解除篩選，再提供擴大範圍；不能暗中改搜全站
5. 題號在支援題目的範圍內精確查找；若在知識庫正文範圍輸入題號，提供「改查題目」明確入口
6. 結果顯示命中欄位、片段及所在文章／科目／章節；表格可辨認是哪一張並直接開啟或定位
7. 每種結果分別計數與截斷；只有真正取得總數才稱共 N 筆，否則寫已顯示 N 筆／還有更多；文章與段落命中不能都算文章篇數
8. 加入搜尋中、載入失敗與重試狀態，不能把讀取失敗當成零結果
9. 新增詳解／表格查詢須評估欄位索引與查詢上限，先在資料庫限縮科目再分頁，不能先取全站前 50 筆再過濾本科

## 建議施工順序

1. 先完成盤查與需求記錄（本輪已完成）
2. 修零結果篩選消失、範圍顯示、重搜篩選保留、計數與結果集合顯示問題
3. 加入本科／本章限制與題目完整解答欄位，補命中片段
4. 納入知識庫表格獨立搜尋與舊比較表內容，統一操作與可分享網址；不在此步強行合併兩套表格內容
5. 確認知識庫相關考題的納入方式與來源，再實作可選範圍
